## 2. 情形 S1：M1 在少于四个数据集上成立

**判定：** 依 `MAIN_PREREG_01.md` §7.1，命题 A 不成立。

**必须这样写：**

> 命题 A 未获支持。M1 与 M2 同时满足的数据集为 N 个（N < 4），未达到预注册要求的 ≥4。

**禁止的表述：**

- 「命题 A 在 N 个数据集上得到支持」——投票规则是一个整体判定，不可按数据集拆分为部分支持；
- 「除 X 数据集外命题 A 成立」——事后剔除数据集等于事后修改判据。

**关于事后解释：** 允许在讨论部分提出对单数据集失败的解释性假设
（例如"该数据集的任务方向性结构较弱"），但须同时满足三个条件：

1. 显式标注为**事后的、未预注册的、未经检验的**；
2. 同时说明该解释在本研究的数据内**如何才能被证伪**，或明确承认在本数据内不可证伪；
3. **不得出现在摘要、结论或任何主张句中**，只能出现在讨论部分。

理由：完全禁止事后解释会使讨论部分失去价值，且是一条大概率会被违反的规则；
一条会被违反的严规不如一条会被遵守的宽规。真正要防的不是"提出假设"，
而是"把事后假设当成结果来陈述"。

**允许的补充：** 可以如实报告哪几个数据集满足、哪几个不满足，并报告各自的点估计与 CI。
可以指出这是一个需要后续研究解释的模式，但**不得**将该模式本身作为对命题 A 的部分支持。

**明确禁止的动作：** 不得因 S1 发生而增加 seed、增加数据集、更换终点、更换尾窗、
或对任一 run 发起重跑。任何因结果不利而发起的代码改动都必须先停止并提交书面理由。

## 3. 情形 S2：某数据集的 `P_R` 区间不跨零

**背景：** P0-B 的头条发现是 `P_R` 在两档负载下均精确为零，
这将"多路径收益"与"集成效应"分离。M2 是该发现在五个数据集上的复现检验。

**判定：** 该数据集不满足 M2，因而不计入 §7.1 的投票。

**必须这样写：**

> 在 X 数据集上，`P_R` 在 [R_low / R_high / 两档] 的 95% CI 不包含零
> （点估计与区间如表所示）。这表明在该数据集上，随机多路径条件相对随机单路径条件
> 存在非零的性能差异，即 P0-B 所观察到的"集成效应为零"不是跨数据集普遍成立的。

**这是一个实质性的科学结果，必须以正文而非脚注呈现。** 它划定了 P0-B 头条发现的适用边界。

**禁止的表述：**

- 把它称为"噪声"或"异常"，除非有独立于本结果的诊断证据支持；
- 只报告 `P_G` 而略过 `P_R`——依 `MAIN_PREREG_01.md` §6.1，② 的定义为 `P_G − P_R`，
  报告 ② 时必须同时报告两个分量（此约束与 `P0B_PREREG_ADDENDUM_01.md` §1.2 对 ②③④ 的要求同源）；
- 因 `P_R` 非零而改用"② 仍显著"来维持原主张——② 显著而 `P_R` 非零，
  意味着几何收益超出集成收益，这与"集成收益为零"是两个不同的命题，不可互相替代。

**若 `P_R` 显著为负：** 依 `P0B_PREREG_ANALYSIS_PLAN.md` §5 第 3 条的同类理由，
负值是预期内的可能结果，不得当作实现缺陷去排查、不得触发重跑、不得调整 seed 或路径。

## 4. 情形 S3：M3 的序被证伪

**背景：** M3 的事前预测序为 `Organ > cifar10 > eurosat`（以 ② 在 `R_high` 上的值排序），
依 `MAIN_PREREG_01.md` §7.1 末句「M3 为单一检验，不参与投票」。

**判定分三档，依 §7 原文执行：**

| 情形 | 判定 |
|---|---|
| 点估计序成立，且两个相邻对 CI 均不重叠 | 序成立 |
| 点估计序成立，但任一相邻对 CI 重叠 | 方向一致、区分度不足 |
| 点估计序不成立 | 序被证伪 |

**「序被证伪」时必须这样写：**

> M3 的事前预测序未成立。观测序为 [实际序]。M3 不参与命题 A 的判定
> （§7.1），故命题 A 的结论不因此改变。
> 但该结果构成对"方向价值 = (…) × 任务的方向性因果结构"这一框架中
> **任务侧因子**的负面证据：本研究据以排序五个任务方向性强度的先验，未获支持。

**这一条要点在于：** 三成分负载门控框架有两个因子，扫描负载侧由 M1/M2 检验，
任务方向性侧由 M3 检验。M3 不参与投票是因为它的先验排序本身缺乏独立标定，
**不是**因为它不重要。序被证伪时，不得以"M3 本就不参与投票"为由淡化。

**禁止的表述：**

- 事后重新定义任务方向性强度的排序依据，使观测序变为"符合预期"；
- 只报告"方向一致"而不报告 CI 重叠的事实（第二档必须写全称，不得简写为"序成立"）；
- 以"Organ 三者取最小值"这一取法作为可调节的自由度——该取法已由 §7 固定，不得改为取均值或中位数。

## 5. 情形 S4：某数据集的设计格不完整

**背景：** 分析脚本对任一 cell 的 seed 数不足 4、或 `validation_history` 非连续 epoch 1..100
一律报错停止。若某个 run 最终无法完成，该数据集不可分析。

**事前承诺：**

1. **投票的分母固定为 5，不完整的数据集在投票算术中计为"未满足"**，不得从分母中剔除。
   理由：允许剔除会使判据严格变松（4/4 通过即达标），而 §7.1 的设计分母是 5。

2. **但在逐数据集的判定表与正文叙述中，该数据集必须标记为 `not evaluable`，
   而非 `not satisfied`。** 二者不可混用：「未通过检验」与「未被检验」是不同的事实，
   把后者写成前者是对读者的误导。投票算术取保守处理，描述性标签取如实处理。

3. 允许在**同一 commit `32edce6`** 下补跑缺失的 run。补跑不是设计变更。
   补跑必须经 `main624_launch.py` 执行（其 preflight 含 legacy 命名空间与冻结产物校验），
   不得手动调用 runner——手动补跑漏传 `--augmentation main_uniform` 会同时移除两层保护
   （见 `CODE_DELTA_68dff0b_32edce6.md` §3.5）。

4. **【操作红线】补跑必须在任何新 commit 之前完成。**
   `main624_launch.py` 的完成判定包含 `metadata.git_commit` 与 `--expected-head` 的前缀比对。
   若在 HEAD 移动之后以新 HEAD 重新运行发车脚本，**已完成的 624 个 run 会全部被判为
   git_commit 不符、移入 quarantine 并重跑**。
   因此：批次结束后若需补跑，顺序必须是「先补跑 → 再 commit 任何文档」。
   一旦已经 commit，则补跑的 run 与既有 run 分属不同 commit，此事实必须记入 ledger，
   且不得通过重跑全部 624 个来"统一" commit。

5. 若补跑不可行（例如数据不可得），该数据集在论文中如实标记为 `not evaluable` 并说明原因，
   命题 A 的判定按第 1 条执行。

6. **不得**用可得的 seed 凑数、不得用其他 seed 的均值填补、不得放宽尾窗定义以纳入未跑满的 run。

## 6. 情形 S5：天花板标注与效应出现的位置重合

**背景：** `MAIN_PREREG_01.md` §8 规定，若某 `(dataset, reliance)` 的结构组尾窗
`train_accuracy` 中位数 > 95%，标注该格处于强饱和区。

**事前承诺：** 若被标注为强饱和的格，恰好也是 ② 显著为正的格，
**必须在报告该效应的同一段落内**给出饱和标注，不得只在附录的诊断表中出现。

表述模板：

> X 数据集在 `R_high` 的 ② 为 [值]，同时该格的结构组尾窗训练准确率中位数为 [值]%，
> 处于强饱和区。在训练侧接近饱和的条件下，泛化侧效应的解释需谨慎：
> 该效应不能被归因于结构组的训练拟合优势。

**背景依据：** `docs/03_EVIDENCE_LEDGER.md` §8d.5 记录了一个"训练侧天花板压缩"假设

只要求标注与效应同处一段，让读者自行判断。

## 7. 情形 S6：GRU 子实验的结果与 Mamba 不一致

**背景：** `MAIN_PREREG_01.md` §7.2 将 GRU 稳健性复现列为**探索性**。
分析脚本已按此收口：Proposition A 与 M3 只对 `backbone == "mamba"` 计算与输出，
GRU 节标题标注 `EXPLORATORY (§7.2)`，保留逐数据集 M1/M2 但不输出投票与 M3。

**事前承诺：**

1. GRU 结果**不得**用于支持或否定命题 A，无论方向。
2. GRU 与 Mamba 一致时，可写「该模式在 GRU 骨干上同样出现（探索性）」，

## 8b. 情形 S8：代码惰性检验结果不利

**背景：** `CODE_DELTA_68dff0b_32edce6.md` §5.1 规定，用主实验 cifar10-Mamba 组中

以直接检验 `68dff0b..32edce6` 的代码改动是否数值惰性。

**事前承诺：**

1. **该检验必须执行，且无论结果如何都必须报告。** 它不是可选的补充分析。
   若结果不利而选择不报告，则 `CODE_DELTA_68dff0b_32edce6.md` §6 的"可主张"一栏全部失效。
2. 若复算值与记录值在量级或符号上出现实质差异，

3. **该检验的结果不得用于调整、筛选或重新解释主实验的任何结果。**
   它回答的是"代码改动是否惰性"这一工程问题，不回答任何科学问题。
4. 检验标准为量级与符号一致，不是逐位相等（两次运行 commit 不同，GPU 非确定性存在）。

   不得在看到复算值之后修改。该节同时载明了本检验对小幅系统性偏移检出力低的事实，

## 8c. 情形 S9：③ 由零转为非零，零对照失效

**背景：** `MAIN_PREREG_01.md` §7.2 已把「③ 在禁用水平翻转后是否由零转为非零」
列为探索性项目，并注明「P0-B 下该零被增强与设计双重决定，本实验可分离」。

但 ③ 在 P0-B 中还承担另一个角色：ledger §8e.4 把「③ polarity 在两档均跨零」
称为**「装置未虚报效应的行为证据」**——即一个零对照，证明测量装置不会凭空产出效应。

**事前承诺：**

1. 若 ③ 在主实验中显著非零，**必须同时声明该零对照在本实验中不再成立**。
   此后任何依赖"装置不虚报效应"的论证（尤其是对 ④ 的解释）必须另行找依据，
   或降低主张强度。不得一边报告 ③ 非零、一边继续援引 P0-B 的零对照。
2. ③ 非零有两种互不排斥的解释：(a) 禁用水平翻转后 polarity 真实起作用；
   (b) 装置在某些条件下虚报效应。本实验**没有**能区分二者的设计。
   因此必须两种解释并列陈述，不得只报 (a)。
3. ③ 仍为探索性（§7.2），无论结果如何都不得升级为确认性主张。
4. 若 ③ 保持跨零，可如实报告零对照在五个数据集上继续成立，
   但**不得**据此声称"已验证装置在所有条件下都不虚报效应"——
   零对照的通过是必要条件，不是充分条件。
